# Jellyfin Two Factor (TOTP)

Plugin for Jellyfin Server 12.1 that adds two-factor authentication with TOTP (RFC 6238, compatible with the usual authenticator apps). It replaces the web client's login with a two-step page: username and password first, then the code from your authenticator app.

## Features

- Two-screen login: username and password first, then the TOTP code. The session is only opened when both are valid.
- Authenticator enrollment with a QR code, protected by a single-use **invitation code** generated by an administrator. Knowing a user's password is not enough to register their authenticator.
- Users can replace their own authenticator at `/TwoFactor/Manage` (for example, when changing phones).
- Administrators manage authenticators and invitations at `/TwoFactor/Admin`: generate and revoke invitation codes and reset a user's authenticator.
- Blocks `POST /Users/AuthenticateByName` (and the obsolete `POST /Users/{id}/Authenticate`) so a session cannot be obtained with just the password.
- Seeds are stored encrypted (AES-256-GCM) with a key that you define.
- Temporary lockout after too many failed attempts, and replay protection for codes.
- Pages in Spanish and English (`?lang=es` or `?lang=en`; defaults to the browser language).

## Requirements

- Jellyfin Server 12.1.x
- To build: .NET 10 SDK and PowerShell

## Build

```powershell
dotnet build -c Release
dotnet test -c Release
powershell -ExecutionPolicy Bypass -File scripts\package.ps1
```

The script creates `dist/Jellyfin.Plugin.TwoFactor_<version>.zip` containing `Jellyfin.Plugin.TwoFactor.dll` and `meta.json`.

## Install

### From a release

1. Download the zip from the latest [release](../../releases).
2. Stop Jellyfin.
3. Create a folder named `Two Factor (TOTP)_<version>` inside the server's `plugins` folder (on Windows this is usually `%ProgramData%\Jellyfin\Server\plugins`) and unzip the file there.
4. Set the `TWOFACTOR_KEY` environment variable (see below). Without it the plugin rejects logins.
5. Start Jellyfin and check in Dashboard > Plugins that it shows as "Active".

### From the Jellyfin plugin catalog

In Dashboard > Plugins > Repositories, add:

```
https://raw.githubusercontent.com/<user>/jellyfin-2fa-plugin-releases/main/manifest.json
```

Then install "Two Factor (TOTP)" from the catalog and restart Jellyfin.

**Install it after completing Jellyfin's initial setup wizard.**

## Configuration

### Encryption key: `TWOFACTOR_KEY` (required)

A key of **exactly 32 bytes, Base64-encoded** (44 characters). Generate one with:

```powershell
[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

```bash
openssl rand -base64 32
```

Docker example (image `lscr.io/linuxserver/jellyfin`):

```yaml
services:
  jellyfin:
    image: lscr.io/linuxserver/jellyfin
    environment:
      - TWOFACTOR_KEY=<the 44-character key>
    volumes:
      - /path/to/config:/config
```

- Keep the key **outside `/config` and its backups**; if it travels with the data, the encryption does not protect that copy.
- **If you change or lose the key, existing seeds become unreadable.** You have to stop Jellyfin, delete `seeds.json` (in `<Jellyfin data folder>/plugins/configurations/TwoFactor/`) and have every user enroll again.
- If the key is missing or invalid, the plugin neither reads nor writes seeds and does not modify the web client's login, so a configuration mistake does not lock anyone out.
- The key protects backups and leaked files, but not against someone who can run code as the Jellyfin user.

### Code parameters (optional)

These set the parameters used when **new** seeds are enrolled.

| Variable | Values | Default |
|---|---|---|
| `TWOFACTOR_DIGITS` | integer from 6 to 8 | `6` |
| `TWOFACTOR_ALGORITHM` | `SHA1`, `SHA256` or `SHA512` | `SHA1` |
| `TWOFACTOR_PERIOD_SECONDS` | integer from 15 to 300 | `30` |

An invalid value makes the plugin reject logins until it is fixed. Each seed keeps the parameters it was created with. Some apps (for example, Google Authenticator) ignore these parameters and always use SHA1, 6 digits and 30 s; with those apps, keep the defaults.

### Invitation codes

Codes have 10 characters, belong to one specific user, are single-use and expire after 24 h (`InviteTtlHours` option in the plugin settings, from 1 to 168). Only their hash is stored. Administrators generate them at `/TwoFactor/Admin`.

**First administrator:** on startup, if no administrator has an authenticator, the plugin writes an invitation code for each administrator without one to the server log (Warning level).

## Usage

1. Open your Jellyfin server. Without a session, the web client sends you to `/TwoFactor/Login`.
2. **First login:** enter your username and password, enter the invitation code your administrator gave you, scan the QR code with your authenticator app and type the first code.
3. **Later logins:** username and password, then the 6-digit code.
4. **Changing phones:** in the menu, "Verificación en dos pasos" / "Two-step verification" (`/TwoFactor/Manage`). It asks for your password again, shows a new QR code and replaces the authenticator once you type a valid code. You can also sign out your other sessions.
5. **Administrators:** "Administrar verificación en dos pasos" / "Manage two-step verification" (`/TwoFactor/Admin`). Lets you generate and revoke invitations and reset a user's authenticator, which closes all of that user's open sessions.

The page also offers Quick Connect and "Forgot password?". Resetting the password does not touch the authenticator.

### Emergency exits

- **Original web client login, one time only:** open `http://server:port/web/?nativelogin=1`. It only applies to that page load.
- **Disable the password-only login block:** set `TWOFACTOR_ALLOW_PASSWORD_LOGIN=true` and restart. While it is set, 2FA can be bypassed with just the password, and the log warns about it on every startup. Remove it as soon as the problem is solved.
- If everything fails, uninstall the plugin.

## Limitations

- Native apps that can only sign in with username and password (Fire TV, Kodi...) can no longer do so. Use Quick Connect, which is authorized from a session with 2FA, or the plugin's page in a browser.
- Quick Connect does not ask for the TOTP code: it inherits it from the session that authorizes it.
- API keys created by an administrator and already-open sessions do not go through 2FA.
- The temporary lockout is kept in memory only and is lost when Jellyfin restarts.
- Behind a reverse proxy, add it under Dashboard > Networking > Known proxies; otherwise all clients appear to have the proxy's IP address.
- It is advisable to also block `/Users/AuthenticateByName` in the proxy.
- Set a password on every account: an account with an empty password can sign in with it through this page.
